🪝
One Module per Resource Type
Each ODB resource gets its own directory with main.tf, variables.tf, outputs.tf, and terraform.tfvars — deploy any subset independently.
🔒
No Hardcoded Secrets
All sensitive values use sensitive = true variable declarations. Credentials stay in .tfvars, never in templates.
🔁
Cross-Module References
The root module wires resources together using module outputs — e.g. VM Cluster references the Exadata Infra ID automatically.
🏭
Jinja2 Template Engine
HCL is rendered from templates/tf/ via Jinja2 — logic stays in Python, keeping templates clean and auditable.
⚙
Autowired Dependencies
The root module automatically resolves inter-resource references — VM Cluster receives the Exadata Infra ID, OCI DB Home receives the VM Cluster ID, and Peering receives the ODB Network ID, all via module.<name>.<output> — no manual wiring needed.

AWS Native IaC

CloudFormation Support — ODB@AWS

Switch from Terraform to CFN in one click — same form, same data, different output format.

  odb-stack.yaml
# Generated by Terraflow Studio
AWSTemplateFormatVersion: "2010-09-09"
Description: Oracle Database @ AWS — ODB Stack
 
Resources:
ProdOdbNetwork:
Type: AWS::ODB::OdbNetwork
Properties:
DisplayName: prod-odb-net
ClientSubnetCidr: 10.0.0.0/24
S3Access: ENABLED
 
ProdExadataInfra:
Type: AWS::ODB::CloudExadataInfrastructure
Properties:
DisplayName: prod-exadata
Shape: Exadata.X9M
 
ProdVmCluster:
Type: AWS::ODB::CloudVmCluster
Properties:
OdbNetworkId: !GetAtt ProdOdbNetwork.OdbNetworkId
CloudExadataInfrastructureId: !GetAtt ProdExadataInfra.Id

Quality Gates

Terraform Validation & Format

Three-layer quality pipeline — form → schema → real Terraform CLI — before a single file is written.

1
Form-Level Validation  /api/validate
Every field is validated on submit — CIDR format, required fields, enum values. Errors surface inline per tab before any HCL is generated.
CIDR check required fields enum values cross-field deps
2
Schema Validation  /api/tf-validate
tf_validator.py simulates terraform validate without needing the Terraform binary — checks HCL structure, provider blocks, resource schemas, variable refs, output refs, and cross-module wiring.
HCL syntax provider block resource schema var.* refs module outputs
3
Terraform / OpenTofu CLI  terraform fmt & validate
When the binary is available (env-var, PATH, or common install paths), the app runs the real terraform fmt and terraform validate — canonical HCL formatting and full provider-schema validation.
terraform fmt terraform validate tofu fmt tofu validate
